# 统一布局约束

`computeLayout(input)` 位于 `public/zipai-layout.js`，是无 DOM、无规则副作用的纯函数。

输入：可视宽高、四边安全区、实际手牌列数、三家公开组数和弃牌数、当前来源、合法按钮数和选择器状态。输出：模式、区域矩形、三家名牌／公开牌／时钟矩形、统一牌张尺寸、内容溢出标记，以及 deck/currentCard/selfHand/seat/public/handCards 锚点。所有坐标均为牌桌坐标；安全区仅平移一次。

- **Portrait**：可用宽小于 680 且非短横屏。房间信息与短状态、上方两家、中央牌堆与当前牌、自己名牌和公开牌、动作、底部手牌。中间保留明确牌张走廊；短屏让公开牌托内部滚动，点「查看」展开到完整尺寸。
- **Compact**：宽大于高且高小于 610。左右信息栏，中间手牌，右下纵向操作栏。当前牌由中间可用高度求解位置，不占手牌。牌托内部滚动；动作多时只有动作栏滚动。
- **Desktop**：其余视口。两侧公开牌，中间牌堆和当前牌，左下自己信息，底部较宽手牌与动作栏。

布局预留五行手牌高度：牌高 + 4×叠放间距 + 标题 + 16px 选中／底部余量。每列保持真实牌宽和 6px 间隔，内容宽取可用宽与列总宽的最大值，22列不会缩成不可辨认的扇面；滚动仅限手牌。选中浮起不会被容器顶部裁切。

结算使用同一布局输出的固定头、固定底部准备与中部滚动内容。桌面/短横屏三列，手机竖屏单列，自己的牌先出现。三家牌尺寸一致，牌组过多时各牌区局部滚动。完整醒牌与底牌随结算正文展示，不能靠压小牌面塞进狭缝。

`applyLayout` 集中读取 visualViewport、安全区和手牌滚动量，再批量写矩形及 CSS 变量。resize 在 requestAnimationFrame 内合并；布局不依赖逐个控件 getBoundingClientRect 回写。指针命中检测是交互例外，只在拖动帧读取目标列。组件结构通过 CSS flex/grid 排列，主区域矩形由引擎独占，样式中没有设备尺寸定位补丁。

节点边界与事件命中是两种验收：纯函数检查核心区域不重叠；浏览器另外验证顶部按钮 elementFromPoint，避免透明容器拦截点击。
