# Motion Director

实现：`public/zipai-motion.js`；运行时 Web Animations API。每条轨迹的 from/to 来自 `computeLayout.anchors`，手打牌优先使用上一次布局的具体手牌锚点。没有固定 vw/vh 旅行位移。

| 事件 | 起点 → 终点 | 反馈 |
|---|---|---|
| deal | 牌堆 → 三家座位，12张背面依次循环 | 380ms 旅行、45ms 间隔 |
| draw / discard | 牌堆／手牌／对方座位 → 当前牌 | 卡牌移动，来源与动作说明，读牌1000ms |
| meld | 当前牌 → 对应公开牌托 | 牌张归属移动 + 吃／碰／扫／开招文字 |
| hu / settle | 当前牌 → 赢家座位 | 胡牌类型、赢家与胡牌张，1100ms |
| wake / flower | 已公开的事件牌 | 单张翻醒、递增醒数／飞飞，1100ms |

事件队列最多48条，按服务端顺序去重。网络接收与 ack 不等待动画；`consume` 完成入队即返回。玩家当前已有合法动作时，手牌与按钮直接采用最新状态，视觉回放不阻塞点击；提交操作会取消旧动效。没有可操作状态时按已脱敏的事件快照展示，结算只在对应回放完成或明确恢复最新状态后打开，不从最终 payload 提前画未翻醒牌。

rotate、hidden、reset、新房间和 dispose 取消动画、定时等待与节点，恢复服务器最新状态；新房间会重置事件 ID 去重集合。队列超过上限或动画异常也恢复最新状态，不改服务器进度。无无限循环动画。

减少动态效果关闭飞行插值，保留必要读牌时长、动作文本和醒数。测试通过暂停 WAAPI 到190ms采集旅行中间帧，并核对 DOM 中 from/to 与布局锚点相等；连续重醒夹具验证逐张顺序和最终结算。真实手机 GPU 帧率未测量，不声称60fps。
