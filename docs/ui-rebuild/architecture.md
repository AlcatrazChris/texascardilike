# 实施架构

```text
RoomClient（原协议不变）→ zipai.js 编排
                         ├─ zipai-view.js：脱敏后的状态 → UI 模型、组件签名
                         ├─ zipai-layout.js：纯几何输入 → 三模式矩形、尺寸、锚点
                         ├─ zipai-input.js：输入状态机、拖动与提交
                         ├─ zipai-motion.js：有界事件队列、真实锚点、取消恢复
                         └─ zipai-dom.js：稳定组件节点、批量几何写入
zipai-tokens.css + zipai.css + zipai-interactions.css：外观与动效
```

设计计划：牌毡 `#194b3d`、深层 `#10392f`、纸牌 `#fffbed`、正文 `#f2f3de`、强调 `#e4c783`、红字 `#be3438`。牌面使用楷体 / 宋体回退，界面使用系统中文字体。金色只用于轮到行动、胡牌、推荐与积分增加；红色用于红字和超时。保留传统长条和上下倒字，不使用仪表盘式装饰。

布局优先级：手牌和动作 > 当前牌与座位 > 公开副露 > 弃牌与辅助信息。空间不足时让副露、弃牌、手牌各自受控滚动并支持展开，卡牌不再无限缩小。结算留在原桌，头部结果、底部准备固定，中间内容独立滚动。三模式由可用空间决定，不识别机型。

所有模块只消费客户端已获授权的数据。任何绘制、动画、测试都不能推导对手暗牌或未来底牌。测试夹具位于 tests，不向生产服务器增加调试端点。后续各阶段的实际验证记录写入 test-matrix 和 final-report。
