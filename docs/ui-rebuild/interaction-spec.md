# 输入、选择器与状态同步

`zipai-input.js` 统一处理 pointer、click、键盘、拖牌预览、取消及提交锁。输入只改变本地布局或发送原有 command，不执行任何吃碰胡规则。

```text
idle → selecting → dragging ⇄ drop-preview → resolved
                    └→ cancelled（越界、隐藏、旋转、状态变化）
selecting/resolved → submitting → waiting-server → resolved
```

- 点击同牌再次取消；键盘 Enter/Space 使用原生按钮点击。
- Alt+方向键执行列内插入、跨列移动／新笔；普通方向键切换焦点。
- 跨过8px移动阈值才拖动。拖牌保持起始握持偏移，以 RAF 更新 transform；目标列描边，插入位置显示金线。
- 向上超过既有安全阈值、离开手牌区、松手仍在牌桌内且最新合法动作允许时才出牌；拖出牌桌取消，超过五张的目标拒绝放入。
- 留白支持横向滑动，拖牌靠边支持滚动。普通轮询不重排手动分组；新牌独立入列；主动「理牌」才重组。
- `input.sync` 在手牌、行动、当前牌或合法动作变化时取消手势。resize、visibilitychange、dispose 都清除 ghost、指针捕获和插入线。
- 提交锁位于输入控制器和编排层；同一个任务中的连续点击只发送一次。按钮以**最新服务端合法动作**为准，不使用历史动画帧的合法动作。

`actionModel` 输出统一按钮描述；单一吃法点击直接执行，多种吃法或胡法在同一个选择器基座中比较。推荐项高亮；浮层边界来自 Layout Engine、内容内部滚动；Escape/返回关闭，Tab循环，打开后聚焦选择项。打开统计或公开牌 dialog 会关闭选择器，避免隐藏焦点陷阱。

座位与公开牌容器固定存在；`patchHTML` 仅在组件签名变化时写入，并保留滚动、选中项焦点。房间准备、重连、动作幂等和权限全部保留原协议。尤其局间重连仍取消本人准备，测试要求再次点击准备，而不是更改服务端行为。
