# 桂林字牌 UI/UX 重构交付报告

## 结算与亮牌后续调整

结算桌面改为上方两家、自己独占下方一行，手机保持单列；三家、摘要、翻醒底牌全部按正常文档流排版，不再交叠定位。摘要区分赢家／胡牌来源、胡醒数、计分公式和三家得分，翻醒底牌单独占行。亮牌与过张采用同一牌面宽高，降低总胡数标题层级，增大副露说明并为文字留足列宽。

十视口增加三家结算与摘要／底牌互不重叠、亮牌和过张同尺寸的真实 DOM 断言。此次仅修改字牌 UI 和截图测试，没有改变计分或游戏规则，也未发布生产。

## 交付状态

本地实现及自动验证完成；没有提交、推送 GitHub 或部署生产环境。回退基线为 `34001800bf645c0dc95e0a029e46e2b4d1a2a9d8`。当前改动可直接在工作区审阅。

本轮没有修改牌堆、胡牌判定、计分、AI、房间协议／认证、API 或德州模块。冻结的核心文件包括 `lib/zipai.mjs`、`lib/rooms.mjs`、`public/app.js`。界面继续消费服务器脱敏后的状态，不能从动画或倒计时推导隐藏应牌者。

## 关键修复

- 三家资料卡使用相同组件尺寸和圆角；外置圆形时钟按数字长度适配，避免遮挡头像。
- 牌桌元素由统一坐标输出定位，手牌高度预留五张叠放和选择抬升，不随按钮或列数上下跳动。
- 手牌与亮牌保留可读最小尺寸；空间不足使用局部滚动和展开查看。结果体可滚动，准备栏固定，自己的牌可到达。
- 更新相同状态不会重建整张牌桌，保留焦点、滚动与手动整理；输入按最新服务器合法操作校验。
- 播放不再阻塞网络状态确认；旋转、隐藏、换房和队列溢出取消旧视觉后恢复最新状态。
- 浏览器测试发现全屏牌桌层会拦截头部按钮，即使几何矩形不重叠；已修正层级，并增加真实点击命中断言。
- 修正按钮字体被父级简写覆盖的问题。未新增运行时依赖，也未下载大型浏览器。

## 验收与限制

格式整理后再次运行：184 项测试全通过、构建检查通过、18 项浏览器测试通过；33 张截图没有更新基线并通过零像素比较。故意改色探针能触发失败，预期／实际／差异图已保存。详细矩阵及运行命令见 [test-matrix.md](test-matrix.md)。

本次实际运行 Windows Edge/Chromium，没有宣称验证 iOS Safari 或真实 Android。十视口以外、软键盘和长期 GPU 性能仍需设备测试。短屏亮牌的局部滚动、竖屏结算的纵向滚动是明确设计取舍；没有把牌缩至无法辨认来强求所有内容一屏展开。

队列过长或生命周期切换会舍弃过时的装饰动画，立即同步服务器状态；不会改变发牌或结算。测试保留原服务器的重连后重新准备逻辑。

开发依赖仅新增锁定版本的 `@playwright/test`；测试报告、trace、截图证据与基线不会进入生产发布包。未增加生产测试端点或环境密钥。回退方法见 [migration-plan.md](migration-plan.md)。

发布仍等待用户明确授权；本报告不把本地通过等同于生产已更新。
