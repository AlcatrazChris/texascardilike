# 房间联机与本地 DeepSeek

## 本地使用

运行 `npm run dev`，或当前工作区使用 `.\.tools\node.exe server.mjs`。打开 `http://localhost:3000`，先选择输入房间号加入、创建联机房间，或下方的人机对局。

创建者在设置中选择 2–9 个座位和 AI 默认难度，随后进入大厅获得 6 位房间号。朋友输入同一房间号与自己的昵称加入。房主可以逐个设置空位的 AI 难度；每位真人先准备，房主再开始；房主可选择 AI 补位或按实际真人数发牌。每手结束后需要重新准备，筹码归零者先领取。普通玩家不能开始牌局、改变 AI 配置或推进下一手。

本地多人测试无需 Redis。不同设备连接同一个本地服务：启动电脑与其他设备连到同一局域网，其他设备访问 `http://<启动电脑的局域网 IP>:3000`。服务默认监听 `0.0.0.0`；如电脑防火墙拦截，需要允许此端口的本地网络访问。同一台电脑可用两个独立浏览器配置或普通 / 无痕窗口模拟不同玩家；复制同一浏览器里的房间身份只会恢复同一个座位。

本地房间默认保存在单个 Node.js 进程内，服务重启后消失。需要持久化或多个服务实例时，配置共享 Redis。房间状态不保存在可修改的客户端牌局凭证中。

## 本地启用 DeepSeek

复制 `.env.local.example` 为 `.env.local`，填写：

```text
SESSION_SECRET=<至少32字符的随机密钥>
DEEPSEEK_API_KEY=<自己的真实密钥>
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_TIMEOUT_MS=1800
```

重启本地服务。服务现在会自动读取 `.env.local` 和 `.env`，优先顺序是启动时已有环境变量、`.env.local`、`.env`。配置文件已被 Git 与部署忽略规则排除。不要把真实密钥写到 `.example` 文件或前端代码中。

本地允许使用单进程限流，因此只配置 DeepSeek key 也能按需调用模型。默认 balanced 策略在每手首次 AI 可选决策（含翻牌前）及后续复杂局面尝试模型；每次请求最多一次、每手默认四次，模型超时或返回错误时自动采用本地决策。实际是否调用取决于局面，不是填写密钥后每个 AI 动作都会请求模型。未配置 key 时全部使用本地 AI。

## AI 策略与难度

本地 AI 从只对随机手牌估算胜率，改为依据对手公开的加注、全下、投入量推断更强或更弱的手牌范围，再模拟未知牌。面对大注时会采用更谨慎的权益余量，并在全下边池场景按自己可参与的筹码计算跟注赔率，减少高估边缘成牌导致的大额亏损。

价值下注的选择概率提高，强牌较少持续过牌，同时保留慢打和控池。牌局规则没有增加“强牌不得过牌”或“必须下注”的限制；任何合法过牌仍被服务端接受。

| 难度 | 默认模拟次数 | 策略差异 |
| --- | --- | --- |
| 轻松 | 96 | 较弱的对手范围推断，较多控池与过牌 |
| 标准 | 240 | 范围推断、价值下注和大额投入防守 |
| 进阶 | 480 | 更精细的范围加权与大额跟注余量，强牌价值下注更积极 |

难度并非通过操纵发牌实现。AI 不读取对手实际底牌或剩余牌堆，仍是近似策略，并非职业级求解器；尚未通过大规模固定牌局对战测量 Elo 或长期胜率。

## Vercel 部署

联机 API 是 `/api/room`，人机 API 是 `/api/game`。在 Vercel 中除 `SESSION_SECRET` 外配置：

```text
UPSTASH_REDIS_REST_URL=<共享 Redis 的 HTTPS 地址>
UPSTASH_REDIS_REST_TOKEN=<Redis REST token>
```

如需模型，再配置相同的 DeepSeek 变量。Redis 同时负责共享房间、乐观并发更新，以及模型的跨实例流量控制。没有 Redis 时，Vercel 的联机房间接口会明确报告未配置，不会使用实例内存伪装共享房间；人机对局仍可用。创建后未活动的房间在 24 小时后过期，活跃操作会续期。

## 同步、身份与规则

- 浏览器约每秒轮询一次服务端，房间所有动作由服务端按规则验证。更新采用 Redis CAS 原子版本比较，避免并发覆盖。
- 每位入座玩家有独立随机身份凭据；服务端只保存哈希，浏览器保存自己的凭据。房间号用于邀请加入，不代替座位身份。
- 返回的当前牌局与每一帧动作都针对接收者脱敏，发牌、牌堆和其他玩家未公开底牌不会以明文发到前端。
- 下注必须符合当前行动席位、牌局版本和合法范围。变更请求带幂等标识，重复提交不会再次扣筹码。
- 每次真人行动提供 45 秒提示计时。到时后显示红色超时计时，继续等待原玩家；不会自动过牌、弃牌或切换玩家。重新连接不重置原行动的计时，玩家仍可继续行动。全下发牌投票仍保留独立的 20 秒默认单次发牌规则。
- 真人退出后本手由 AI 临时接管；房主退出时转交房主。下一手可由房主决定 AI 补位或按现有人数发牌。新玩家可在两手之间加入并准备，已有身份可以刷新后返回房间。
- 清除浏览器存储会丢失座位凭据；当前没有账户密码恢复系统。
- 最近 100 个动作快照用于恢复播放。离线太久超出缓冲时直接同步最新局面并提示，不伪造遗漏动作。

## 已验证与限制

测试覆盖了多身份底牌隔离、所有动作帧脱敏、重复下注防重、并发加入、越权和过期版本拒绝、完整多人对局筹码守恒、每人积分、房主权限、退出与接管、超时和 Redis CAS 命令。

双浏览器独立身份已实际验证创建 / 加入、AI 难度同步、提前开始补位、轮流操作、结算、下一手、刷新恢复、退出接管，以及切换回人机模式。DeepSeek 已完成本地真实接口调用验证。云端 Redis 负载测试和线上发布仍未执行。新增准备、领取、投票及积分轮数规则见 [牌桌操作说明](TABLE-PLAY.md)。

## 重连与显式准备

浏览器按房间保存座位凭据，并使用随机浏览器身份处理加入请求重试。输入相同房号会优先恢复原座位，不另建玩家，也不重置筹码或底牌。昵称不能作为身份凭证；同昵称的新身份会被拒绝。每手准备绑定当前手数，结算和重新入座后均未准备，必须主动点击。

旧版房间已存在的离线重复席位，房主可在发牌前点击「移除离线席位」；服务端要求目标离线满 30 秒，不能移除在线玩家或冒用其身份。
