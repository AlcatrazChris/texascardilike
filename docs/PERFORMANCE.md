# 空间与下注延迟优化

2026-10-27，Windows 本地测量。清理前工作区 1014.17 MiB，其中 `.tools` 为 1013.87 MiB，源码和配置约 0.3 MiB。主要是测试浏览器配置与模型 / 扩展缓存、npm 下载缓存、Vercel CLI。源码无运行时 npm 依赖。`scripts/clean-cache.ps1` 对已解析的工作区路径做边界和链接检查，保留本地 Node、npm、授权状态及配置。

发布并清理后复核：工作区 **92.72 MiB**，释放约 **921.45 MiB（90.86%）**。其中便携 Node 为 81.18 MiB，源码与配置约 0.32 MiB。Vercel CLI、浏览器配置和截图已移除；登录状态、项目关联和 `.env.local` 保留。清理后再次启动本地服务，首页、新前端模块和流式开局均通过检查。

9 人桌、12 手跟注 / 过牌结算后的固定场景，`scripts/benchmark.mjs` 可复测。牌堆随机导致数据大小有轻微波动：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 人机加密凭证 | 54,268 B | 约 6,035 B |
| 房间持久化体积 | 532,957 B | 约 27,110 B |
| 无变化轮询回复 | 41,028 B | 约 816 B |
| 本机模拟房间 12 手总耗时 | 4,544 ms | 约 1,179 ms |

体积约分别减少 89%、95%、98%。模拟耗时含本地存储编解码和状态操作，不等于线上网络或完整对局耗时；未把本地文件大小当作运行时 RSS 内存。内存房间存储保存压缩文本，读取后按请求解压为隔离对象；动作快照在克隆前移除牌堆、旧历史和日志，减少重复分配。

下注体验变化：

- 人机接口支持 `Accept: application/x-ndjson`，先返回合法玩家动作帧，随后返回 AI 动作和最终认证凭证。原 JSON 接口继续兼容。帧在服务端过滤隐藏手牌。
- 网络接收和动作动画独立，AI 计算与已确认动作的播放重叠。筹码飞行 650→380 ms，下注停留 1100→480 ms，普通动作 900→320 ms；亮牌仍保留 1100 ms，结算 850 ms。
- 联机按钮操作会取消尚在等待网络的轮询，优先发送动作；已经在播放的确认动作仍按顺序展示。无变化轮询保留成员在线状态、准备状态与计时，但不重复发送牌局和历史。
- DeepSeek 缓存读取和限流租约改为一个 Redis 原子请求；模型超时包含之前的缓存 / 预算等待，结束后的缓存写入与租约释放并发处理，仍保留失败回退、共享限流和手数预算。

浏览器人为延迟剩余响应 1500 ms 的场景，玩家跟注约 109 ms 已显示，等待后续结果时继续保留逐个动作。模拟断流时保留上一个有效凭证，恢复原筹码并提示重试。该数字为本地受控测试，不承诺公网响应时间。

正式环境真实浏览器的一次 2 人桌加注测试，玩家下注在约 337 ms 显示，AI 等后续动作播放后约 2844 ms 恢复操作，无 JavaScript 错误。DeepSeek 云端日志确认请求成功。公网测量是该次样本，不是延迟 SLA。

兼容与恢复：压缩数据在认证加密内部标记格式，能读取旧有效凭证；Redis 包装保留顶层版本供原 CAS 使用，并能读取旧 JSON 房间。旧部署代码无法读取新压缩格式，因此恢复发布时应使用包含此解码器的版本。解压限制为 8 MiB，密文篡改仍被拒绝。所有记录与计分规则保持原有保留范围。

验证覆盖压缩与旧数据迁移、原子并发、逐手准备、全下 / 正常摊牌、重连、轻量轮询、流式中文分块、慢 AI 首帧、断流恢复，以及联机操作抢占轮询。完整测试命令：`.tools/node.exe --test tests/*.test.mjs`。
